# Investigation Instructions

These instructions apply only inside this investigation and specialize, without
weakening, inherited project instructions.

- Begin each scientific direction with the smallest direct prototype that can
  answer or sharpen one question. Briefly inspect readily available prior
  practice only when it could change an unfamiliar method's interpretation.
- Within the charter, choose order, depth, tools, examples, representations,
  and stopping points according to the developing science.
- Read `CHARTER.md`, the current state in `PROGRESS.md`, and only registry
  entries or optional records material to the current prototype.
- Preserve material assumptions, units, coordinates, uncertainty, source
  meaning, and evidence status. Keep accepted basis, direct evidence, and
  provisional working contracts distinct.
- Test only the scientific spine of the current prototype. Do not test internal
  behavior of established dependencies unless it is the governing question.
  When a working contract affects interpretation, use the smallest check that
  could challenge a claim or detect a material convention mismatch. Do not use
  a provisional claim as the oracle or add proof, tests, or debugging
  scaffolding merely to defend it.
- On a material contradiction or unexplained sensitivity, distinguish
  implementation error from scientific failure, then reconsider the weakest
  relevant contract, assumption, representation, or method.
- Register a generated output in `PRODUCTS.toml` only when it must persist
  because it affects interpretation, supports later prototypes, or will be
  handed off. Leave other work in scratch and elsewhere reference product IDs.
- Keep durable conclusions, limitations, and next moves in `PROGRESS.md`.
  Preserve material changes in dated checkpoints; update `CHARTER.md` only when
  its purpose, scope, or governing question changes. After a material change or
  before a pause or handoff, update affected state, products, and contracts.
- Use Git—not backup, snapshot, before-edit, or duplicate-tree copies—for
  ordinary tracked-file history and recovery. Never create such copies merely
  for rollback or “just in case” safety. Commit only when authorized. Version
  history is provenance, not proof.
- Request direction when a choice would replace the scientific purpose, exceed
  authority, require project-wide change, or depend on information that cannot
  be responsibly inferred.

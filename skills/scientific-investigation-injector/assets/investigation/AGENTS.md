# Investigation Instructions

These instructions apply only inside this investigation and specialize, without
weakening, inherited project instructions.

- Begin every new scientific direction with the smallest direct prototype that
  can answer, distinguish, or sharpen one question.
- Keep each prototype bounded to its current scientific purpose.
- Within the charter, choose order, depth, tools, examples, representations,
  and stopping points according to the developing science.
- Read `CHARTER.md`, the current state in `PROGRESS.md`, relevant entries in
  `PRODUCTS.toml`, and active local contracts before continuing work.
- Preserve assumptions, units, coordinates, uncertainty, source meaning, and
  evidence status when they affect interpretation.
- Test only the scientific spine of the current prototype. Do not test internal
  behavior of established dependencies unless it is the governing question.
- Register scientifically relevant figures, intermediate data, calculations,
  and reports outside disposable scratch space.
- Move durable conclusions and limitations from conversation or scratch work
  into investigation files.
- Preserve material history in dated checkpoints rather than silently
  rewriting it.
- When purpose, scope, or the governing question changes, update `CHARTER.md`
  and record the evidence and reason in `PROGRESS.md`.
- At a natural boundary, update prototype outputs, the registry, current state,
  and the next scientific question.
- When Git commits are authorized by the user or inherited project instructions,
  preserve coherent changes at meaningful scientific boundaries. Do not infer
  commit authorization from these local instructions. Version history is
  provenance, not proof.
- Request direction when a choice would replace the scientific purpose, exceed
  authority, require project-wide change, or depend on information that cannot
  be responsibly inferred.
